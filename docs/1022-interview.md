### 10 月 22 日离线考场

1. 提前在主机安装并启动 Docker Desktop（Linux 容器），校准 Windows 系统日期、时区与时间；程序不会访问互联网校时。
2. 解压本次源码包，将本次 `1022-images.tar` 放到同一项目目录，双击 `start-offline.bat`，自动导入镜像并离线启动。
3. 主机与考生连接同一个路由器。考生访问 `http://主机局域网IP:8080`，使用桌面 Chrome 或 Edge；不要填考生自己的 localhost。
4. 主机防火墙允许 TCP 8080 入站，路由器关闭访客网络或无线客户端隔离；考场期间主机保持开机、不休眠。
5. 启动脚本显示主机北京时间；开考前核对。容器系统时钟也须与主机一致，Docker 休眠恢复后若有偏差先重启 Docker Desktop。
6. 14:50 前不提供题目；到点学生列表自动刷新，也可手动刷新。15:50 停止编辑、保存和自测，并发起交卷。
   前端按服务器返回时间和浏览器单调时钟倒计时，每 5 秒校准，不读取学生电脑的日期计时。
7. 后台每 5 秒扫描到期作答；保留 5 秒交卷传输余量后，对已保存的代码判题、保存成绩。
   学生关闭浏览器也会收卷，判题完成时间随队列与代码耗时延后，不能继续答题。
8. 输入后自动保存，界面显示保存状态；网络中断时保留本机未同步修改并重试，恢复后可继续。
   如果一直断线到截止，服务器只能收取截止前已成功保存的答案，无法收到仍留在学生电脑上的内容。

全屏由浏览器提供，用户仍可按 Esc 退出；系统通过遮挡题目要求恢复全屏，不是操作系统级锁机。
本场关闭退出次数自动收卷，不影响按截止时间收卷。新建考试可在“作答环境”单独开启该选项。

学生首次登录必须填写本人姓名。弹窗不能关闭或跳过，未登记时业务接口也拒绝访问。
姓名保存到数据库，换电脑或重新登录不再要求填写。允许同名，用账号区分；
登记的是自报姓名，不进行证件验证。

三位老师均可在“班级看板”查看本班名单、姓名和登记状态，点击刷新更新。
发题选择“按班级 → 1022二面”。已发布到本班的试卷可共同监考、查看结果和批阅。
草稿和个人指派试卷归创建老师；跨班试卷只对有权管理全部目标班级的老师共享；
带非空白名单的试卷仅创建老师可见，避免额外受众的成绩被开放。

## 在另一台 Windows 电脑启动

准备 Docker Desktop（Linux 容器模式，带 Docker Compose），复制完整项目目录。
首次构建需要联网下载镜像、Python 和 npm 依赖。

1. 启动 Docker Desktop，等待引擎就绪。
2. 双击根目录 `start-interview.bat`，或在根目录执行：

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start-interview.ps1
   ```

3. 脚本生成本机专用 `.env.interview`，构建前后端及判题沙箱，启动独立数据库等服务，自动建表、建号、导入考试草稿。
4. 主机访问 `http://localhost:8080`，其他电脑访问 `http://主机局域网IP:8080`。
   若局域网不能访问，在 Windows 防火墙允许应用端口 8080 入站。

更换端口：修改 `.env.interview` 中的 `INTERVIEW_PORT`，重新运行脚本。
初始化可重复执行，已有密码、姓名、登记状态及作答数据保留。
账号或班级与其他来源的数据冲突时整体回滚本次建号，不覆盖其他数据。
此入口不额外创建管理员或演示账号。

### AI 和编程题

账号登录、姓名登记、名单和已有试卷作答不依赖邮箱服务。
AI 拆题、AI 评分需要可用模型服务及网络。在 `.env.interview` 填写
`SILICONFLOW_API_KEY`、`SILICONFLOW_BASE_URL`、`SILICONFLOW_CHAT_MODEL` 后重启。
未配置模型时 AI 功能不可用。
启动配置已包含专用 go-judge 沙箱及四种语言工具链。判题不需要 AI 服务。
沙箱只开放 Compose 内部接口，后端和 worker 通过 `http://judge:5050` 访问。
构建默认使用中科大 Debian 镜像，可在 `.env.interview` 设置
`DEBIAN_MIRROR=http://deb.debian.org` 改回上游源。
底层运行及缓存协议见 [go-judge 官方 API](https://docs.goj.ac/api)，
软件源配置见 [中科大 Debian 镜像说明](https://mirrors.ustc.edu.cn/help/debian.html)。

后续修改代码后，在可联网、相同 CPU 架构的电脑运行启动脚本完成构建，再重新导出镜像：

```powershell
$images = docker compose --env-file .env.interview -f docker-compose.interview.yml config --images | Sort-Object -Unique
docker save -o 1022-images.tar $images
```

将项目和 `1022-images.tar` 一起带到目标电脑，导入后启动：

```powershell
docker load -i 1022-images.tar
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start-interview.ps1 -Offline
```

源码压缩包不包含镜像。新电脑默认建立空白账号，不会自动带走旧电脑作答数据。

## 接口和数据结构

- 新表 `class_teachers(class_id, teacher_id)` 联合主键，表示班级协管。
  原 `classes.teacher_id` 保留为创建老师，协管老师不计入学生人数。
- 本批学生 `student_profiles.extra_info` 保存 `interview_batch: "1022"`、
  `identity_required` 及登记后的 `identity_confirmed_at`。
- 登录及 `GET /api/v1/auth/me` 的用户数据增加 `requires_identity_confirmation`。
- `POST /api/v1/auth/identity` 接收 `{"name": "张三"}`。
  姓名去除首尾空白后须为 1～50 字符，不接受控制字符。保存到 `users.nickname`，
  清除待登记状态，返回最新用户数据。重复提交不会覆盖已完成登记。
- 未登记账号可读取本人信息、功能开关和提交姓名；其他依赖登录身份的 HTTP 业务接口返回 403。
- 班级成员响应增加 `display_name`、`requires_identity_confirmation`。
- `POST /api/v1/assessment/papers` 的 `file_id` 现在可省略：省略时创建
  `awaiting_review` 空白草稿，随后通过原题目保存接口录题。
- 编程题 `language: "multi"` 允许学生选 Python、Java、C、C++。
  该模式答案形如 `{"code":"程序源码","language":"cpp"}`，复用答案 JSONB 字段；
  单语言旧题继续兼容字符串答案。自测接口新增可选 `language`，后端校验题目允许的语言。
- 编译产物在判题后释放；Java 以 JAR 保存所有 class 文件，支持内部类和辅助类。
- `server/app/data/exam_1022.json` 是可迁移的题目数据，`python -m app.exam_1022`
  通过与命题接口相同的服务导入草稿。`scripts/build-1022-exam.py` 可重建数据文件；
  它不会覆盖已经导入数据库的题目。
