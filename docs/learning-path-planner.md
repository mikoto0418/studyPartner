# 学习路径规划器设计

## 问题

旧版 `LearningPathPlanner` 主要按“先、再、然后、最后”切句；当教师输入“机器学习入门 / 从 GitHub 拉库到自部署 / 跑通常见实验”时，系统会生成“理解概念、阅读材料、完成练习、提交总结”这类空泛节点，不能帮助老师真正发布可执行路径。

## 设计来源

本实现不复制第三方开源项目代码，只采用公开、通用的教学设计方法论：

| 方法 | 在规划器里的用途 |
|---|---|
| Backward Design | 先定义学习结果和验收证据，再安排活动 |
| Merrill First Principles | 以真实任务为中心，按激活、示范、应用、整合推进 |
| Gagne Events | 补齐目标说明、指导、练习、反馈、评估和迁移 |

这些是教学设计框架，不是代码依赖，因此不引入额外开源协议义务。

## 当前策略

### 1. 场景识别

当标题、目标或规划中出现以下组合时，进入“项目复现/部署实验”模板：

- GitHub、仓库、拉库、代码库
- 部署、自部署、环境、依赖
- 跑通、实验、复现、baseline、demo

这类任务会生成更具体的节点：

1. 确定目标仓库与验收标准
2. 补齐复现实验前置基础
3. 拉取代码并阅读项目入口
4. 创建隔离环境并安装依赖
5. 准备数据、权重与配置文件
6. 跑通最小 demo 并定位报错
7. 复现一个常见实验并记录指标
8. 整理部署脚本与复现说明
9. 提交复现实验报告与后续问题

### 2. 一般技能路径

没有命中项目复现场景时，使用“目标与前置 → 输入与示范 → 练习与迁移 → 评估与复盘”的通用结构。

### 3. 教师大纲增强

如果教师已经写出 3 个以上明确步骤，系统不再粗暴覆盖，而是保留教师大纲，并给每个节点补充：

- 节点类型
- 所属阶段
- 预计时长
- 节点产出
- 完成标准
- 资源提取结果

## 数据合同

规划器仍返回原有结构：

```json
{
  "stages": [],
  "nodes": [],
  "edges": [],
  "resources": [],
  "summary": ""
}
```

节点 `config` 新增：

| 字段 | 说明 |
|---|---|
| `source` | `instructional_design_planner` |
| `frameworks` | 使用的教学设计框架列表 |
| `stage_order` | 所属阶段序号 |
| `deliverable` | 本节点产出物 |
| `success_criteria` | 完成标准 |

## 后续升级

- 接入模型网关，让 LLM 在同一 JSON contract 下做主题细化。
- 增加“论文阅读 / 数学建模 / 编程项目 / 考试备考”等场景模板。
- 结合学生 Memory 和班级洞察，按基础水平生成分层路径。
- 在前端节点卡片上直接显示产出物和完成标准。
