# 教师端与 Agent 平台重构设计方案

## 结论

教师端当前最大的问题不是界面不够好看，而是信息优先级错位：教师每天打开系统，最需要先知道“班级现在发生了什么、谁需要我介入、我下一步该做什么”。因此教师工作台应从“批改作业列表 + 聊天框”重构为“班级态势驾驶舱 + 可执行 Agent 工作台”。

班级学情记忆也不应展示 `goal / weakness / interest_area` 这类分类数量。分类只是系统内部组织方式，对教师没有直接价值。教师需要看到的是内容：哪些学生遇到同一类问题、证据来自哪里、影响哪些任务、系统建议老师怎么干预。

## 当前落地状态

| 模块 | 状态 | 说明 |
|---|---|---|
| LearningInsight 洞察对象 | 已落地 | 新增 `learning_insights` 表，支持证据链、影响学生、建议动作和状态流转 |
| 班级学情洞察卡片 | 已落地 | 教师班级看板展示真实洞察内容，不再把 memory category 数量作为重点 |
| 洞察状态处理 | 已落地 | 教师可将洞察标记已读或解决，系统刷新时保留关闭状态 |
| 大量学生选择器 | 已落地 | 创建班级、学习路径、普通任务均使用分页搜索弹窗 |
| 教师 Agent 工作台 | 首版已落地 | 教师首页右侧已接入班级态势快照，支持生成班级简报、干预计划、分层任务草稿和学生反馈话术；写入/发布类工具调用仍需老师确认后执行 |

## 一、教师工作台的信息架构

### 第一屏优先级

| 优先级 | 模块 | 教师真正要回答的问题 | 当前问题 | 新设计 |
|---|---|---|---|---|
| P0 | 班级概况 | 今天这个班整体怎么样？ | 班级信息在二级页，工作台被批改作业占据 | 工作台第一屏展示班级态势、风险、进度、活跃度 |
| P0 | 需介入学生 | 谁需要我今天关注？为什么？ | 只展示待提交/待批改，不展示学习状态 | 按风险原因聚合：进度低、长期未活跃、薄弱点集中 |
| P1 | 教学建议 | 下一节课/下一次任务该怎么调整？ | Agent 只是聊天，需要老师主动问 | Agent 自动给出可执行建议和一键草拟动作 |
| P1 | 待办队列 | 我有哪些必须处理的事？ | 待批改占据主视觉 | 批改、公告、任务反馈合并为右侧待办队列 |
| P2 | 原始数据 | 我想追溯证据时看什么？ | 数据散在多个页面 | 每个洞察可展开证据链：学生、来源、时间、原文片段 |

## 二、班级学情记忆看板应该展示什么

### 不展示什么

不要把内部分类数量作为核心内容：

- 学习目标 1
- 兴趣方向 1
- 学习偏好 1
- 学习习惯 1
- 薄弱项 1

这些最多是调试指标，不是教师决策信息。

### 应该展示的内容模型

班级记忆应转成“洞察卡片”：

| 字段 | 含义 | 示例 |
|---|---|---|
| 洞察标题 | 老师一眼看懂的问题或机会 | “3 名学生在动态规划状态转移上反复卡住” |
| 影响范围 | 影响哪些学生/班级比例 | 3/27，集中在进度 40%-60% 学生 |
| 证据片段 | 从对话、作业、复盘里抽出的原文摘要 | “不会确定 dp[i] 的含义”“总是把选择和状态混在一起” |
| 来源 | 证据来自哪里 | AI 对话 5 条、任务提交 2 条、复盘 1 条 |
| 严重度 | 高/中/低，区分风险和普通偏好 | 高 |
| 建议动作 | 系统建议老师做什么 | “下一节课增加 15 分钟状态定义练习” |
| 一键动作 | Agent 可以直接做什么 | 生成讲解草案、生成补充练习、给相关学生发提醒 |

### 新看板分区

1. **班级洞察**
   - 按主题聚合，不按 memory category 聚合。
   - 每条洞察都有证据和影响范围。

2. **共性薄弱点**
   - 只展示可教学干预的内容。
   - 例：动态规划状态定义、文献综述结构、实验复现实操。

3. **学生分层**
   - 领先组：可给扩展任务。
   - 稳定组：按路径继续推进。
   - 风险组：需要教师介入。

4. **最近变化**
   - 哪些学生本周状态变好/变差。
   - 哪些共性问题突然增加。

5. **Agent 建议动作**
   - 生成班级公告。
   - 生成分层任务。
   - 生成课堂讲解提纲。
   - 生成一对一学生反馈。

## 三、教师 Agent 不应只是聊天

### 当前问题

现在教师 Agent 是一个右侧对话框。它能回答问题，但不会主动把系统数据变成工作流，也不会沉淀成教学动作。这会让它看起来像“带知识库的聊天”，不是 Agent 平台。

### Agent 应升级为任务型工作台

| Agent 能力 | 输入 | 输出 | 可执行动作 |
|---|---|---|---|
| 班级诊断 Agent | 班级路径、复盘、记忆、任务提交 | 本周班级健康报告 | 生成简报、导出报告 |
| 任务设计 Agent | 教学目标、学生水平、截止时间 | 分层任务草案 | 发布任务、保存草稿 |
| 批改辅助 Agent | 学生提交、评分规则 | 评分建议、反馈草案 | 写入批改意见 |
| 干预计划 Agent | 风险学生列表、证据链 | 一对一干预策略 | 生成提醒、创建辅导任务 |
| 资源推荐 Agent | 薄弱点、知识库、B 站学习记录 | 补充资料包 | 推送到班级/个人 |
| 教学复盘 Agent | 本周行为数据 | 教师复盘摘要 | 生成周报 |

### Agent 交互形态

不要只有聊天输入框，应有三层：

1. **洞察触发**
   - 系统自动发现问题，推送建议卡片。

2. **模板化动作**
   - “生成补充练习”
   - “给风险学生生成提醒”
   - “把这个洞察转成课堂讲解”

3. **自由对话**
   - 当老师需要追问时再进入聊天。

这样 Agent 才像“会干活的教学助手”，而不是“另一个问答框”。

## 四、作为 Agent 平台还能扩展什么

### 学生端 Agent

- 学习计划 Agent：把目标拆成日程、任务、资源。
- 反思复盘 Agent：每天生成复盘，追问关键原因。
- 知识库问答 Agent：基于个人资料和课程资料回答。
- 任务陪跑 Agent：跟踪任务进度，提醒卡点。
- 视频学习 Agent：根据 B 站观看记录生成笔记和待办。

### 教师端 Agent

- 班级运营 Agent：自动发现班级风险和机会。
- 教学设计 Agent：基于目标生成路径、课堂活动和作业。
- 分层辅导 Agent：按学生画像生成不同任务。
- 批改与反馈 Agent：批量生成个性化反馈草案。
- 教学简报 Agent：生成日报/周报/家校沟通摘要。

### 管理端 Agent

- 模型运维 Agent：检测模型失败率、成本、延迟，推荐路由调整。
- 内容安全 Agent：审计敏感信息和异常对话。
- 数据质量 Agent：发现空档案、无效记忆、坏知识库切片。
- 平台增长 Agent：统计活跃路径和留存原因。

### Agent 平台的关键基础能力

| 基础能力 | 为什么重要 |
|---|---|
| 工具调用 | Agent 必须能创建任务、发通知、写批改，而不是只回答 |
| 证据链 | 所有建议必须能追溯到数据来源 |
| 人在回路 | 发布任务、发送通知、删除记忆等动作必须老师确认 |
| 长短期记忆 | 支撑连续陪伴，而不是一次性问答 |
| 任务队列 | 长任务如生成班级报告、批量批改需要异步执行 |
| 审计日志 | 教学场景必须知道 Agent 做过什么、为什么做 |

## 五、大量学生选择器设计

### 当前问题

`el-select multiple` 只适合 5-20 个选项。几十个学生时会出现：

- 搜索能力弱。
- 已选学生不可管理。
- 无法按班级、年级、状态筛选。
- 不知道会影响多少人。
- 大量选择时视觉拥挤。

### 新组件：StudentPickerDialog

适用于创建班级、分配任务、发布路径、公告指定学生。

```text
┌──────────────────────────────────────────────────────────────┐
│ 选择学生                                         已选 38 人   │
├──────────────────────────────────────────────────────────────┤
│ 搜索姓名/账号/学号  年级筛选  班级筛选  活跃状态  风险标签    │
├──────────────────────────────┬───────────────────────────────┤
│ 学生表格                       │ 已选学生                       │
│ □ 徐睿哲  student  2024级       │ 徐睿哲    移除                 │
│ □ 李明    liming   2024级       │ 李明      移除                 │
│ □ ... 支持分页/虚拟滚动         │ 批量清空 / 保存为分组           │
├──────────────────────────────┴───────────────────────────────┤
│ 全选当前筛选结果 / 反选 / 导入学号名单 / 取消 / 确认选择       │
└──────────────────────────────────────────────────────────────┘
```

### 交互细节

- **表格选择**：不是下拉列表，使用可排序表格。
- **服务端分页**：默认 `page_size=50`，支持搜索，不一次性加载所有学生。
- **筛选器**：班级、年级、专业、活跃状态、是否风险学生。
- **批量选择**：支持“选中当前页”和“选中当前筛选结果”。
- **已选侧栏**：独立显示已选对象，可搜索、移除、清空。
- **选择摘要**：确认前显示“将影响 38 名学生，覆盖 2 个班级”。
- **导入名单**：支持粘贴学号/账号，一次性匹配。
- **保存分组**：常用名单可保存为“论文组”“实验组”等。

### 数据接口建议

```http
GET /api/v1/users?role_code=student&page=1&page_size=50&keyword=&grade=&class_id=&status=
POST /api/v1/student-groups
GET /api/v1/student-groups
POST /api/v1/student-picker/resolve
```

`resolve` 用于把粘贴的学号/账号批量解析成用户 ID，并返回未匹配项。

## 六、落地顺序

### Phase 1：信息架构调整

- 已落地：教师工作台首屏改为班级态势驾驶舱。
- 已落地：待批改作业缩成右侧待办队列。
- 已落地：班级学情记忆看板改为洞察卡片。

### Phase 2：Agent 工作台

- 已落地首版：教师工作台右侧提供任务型 Agent 面板。
- 已落地首版：增加生成班级简报、干预计划、分层任务草稿、反馈话术四类入口。
- 待增强：将 Agent 草稿进一步接入任务发布、公告发布、提醒创建等确认式工具调用。

### Phase 3：学生选择器

- 抽 `StudentPickerDialog` 公共组件。
- 替换创建班级、路径任务、普通任务、公告发布里的多选下拉。

### Phase 4：后台数据升级

- 从 memory category 聚合升级为 insight 聚合。
- 后端返回洞察卡片：标题、证据、影响学生、建议动作、来源。
- Agent 动作写入审计日志。

## 七、验收标准

- 教师打开工作台 5 秒内能回答：哪个班最需要关注、哪些学生要介入、今天要处理什么。
- 班级看板不再以分类数量作为核心内容，而是展示可行动洞察。
- 教师 Agent 至少有 4 个非聊天动作：生成任务、生成反馈、生成班级简报、生成干预计划。
- 所有批量选学生入口不再使用多选下拉。
- Agent 的每条建议都能看到证据来源。
