# AI 伴学与智能体协同平台 PRD 文档

版本：V1.0
适用阶段：实验室 MVP
部署方式：实验室工作站本地部署 + Cloudflare Tunnel 域名访问
主要模型接口：硅基流动 OpenAI 兼容接口
产品定位：面向实验室的 AI 伴学平台与智能体协同系统

---

## 一、项目背景

当前实验室学生在日常学习、项目推进、资料整理、任务跟进等方面存在以下问题：

1. 学习过程缺少持续记录，老师难以及时了解学生真实学习状态。
2. 学生的学习任务、计划、资料、笔记、视频学习记录分散在不同平台。
3. 传统任务管理系统只能记录任务结果，不能理解学生长期学习行为。
4. 实验室知识资料缺少统一沉淀，历史资料复用效率低。
5. 学生缺少一个能够长期陪伴、记忆个人学习习惯并自适应调整建议的 AI 伴学工具。
6. 老师和管理员缺少对学生学习热力、任务完成情况、资料使用情况的统一管理视图。

因此，本项目拟建设一套面向实验室内部使用的 AI 伴学与智能体协同平台，以“学习行为记录 + 个性化智能体 memory + 实验室知识库 + 老师任务协同”为核心，形成一个可持续成长的实验室 AI 学习平台。

---

## 二、产品定位

本平台定位为：

> 面向实验室的 AI 伴学与智能体协同平台。

系统不是普通的学习打卡系统，也不是单纯的聊天机器人，而是围绕学生长期学习过程，构建一个具备记忆、复盘、建议、协同和知识沉淀能力的智能学习平台。

平台初期服务于实验室内部，采用管理员创建账号的方式控制用户范围，部署在实验室工作站，通过 Cloudflare Tunnel 映射域名供实验室成员访问。

## 三、产品目标

### 3.1 MVP 阶段目标

MVP 阶段优先完成一个实验室内部真正能用的闭环系统：

1. 管理员可以创建学生、老师账号。
2. 学生登录后进入个性化仪表盘。
3. 学生可以使用 TODO、便签、倒数日、书签、学习时长统计等基础工具。
4. 仪表盘支持模块化自定义、拖拽排序和布局保存。
5. 老师和管理员可以发布公告、下达任务。
6. 学生可以查看公告、接收任务、完成任务。
7. 平台可以记录学生学习行为。
8. 每个学生拥有一个独立 AI 伴学智能体。
9. 智能体可以基于学生行为和历史交互形成自适应 memory。
10. 系统每天 0 点自动复盘前一天学习行为，并整理 memory。
11. 支持学习热力图、月日历计划和学习数据统计。
12. 支持 iframe 嵌入哔哩哔哩学习链接，记录标题、时长、分集等学习信息。
13. 支持实验室共享知识库，学生和老师可上传学习资料。
14. 后端优先接入硅基流动 OpenAI 兼容接口，后续预留多模型路由能力。
15. 系统部署在实验室工作站，并通过 Cloudflare Tunnel 绑定域名访问。

### 3.2 长期目标

后续将平台扩展为完整的智能体协同系统：

1. 学生伴学智能体。
2. 学习规划智能体。
3. 任务督导智能体。
4. 知识库问答智能体。
5. 资料整理智能体。
6. 教师助手智能体。
7. 管理员运维智能体。
8. 多智能体协同工作流。
9. 自动生成学生周报、月报和阶段评价。
10. 实验室知识资产长期沉淀。

1. 管理员。
2. 老师。
3. 学生。

2. 创建老师账号。
3. 管理用户状态。
4. 配置角色权限。
5. 管理实验室知识库。
6. 配置模型 API。
7. 配置通知渠道。
8. 查看系统日志。
9. 查看全实验室学习概览。
10. 发布全体公告或指定公告。
11. 下达实验室任务。
12. 管理平台运行状态。

### 4.2 老师

老师主要负责学生学习任务管理、计划制定、学习状态查看和指导建议。

核心职责：

10. 查看学生阶段性复盘摘要。

### 4.3 学生

学生是平台主要使用者，使用个人仪表盘、学习工具、AI 伴学智能体和知识库。

核心功能：

1. 登录平台。
2. 查看个人仪表盘。
3. 自定义仪表盘模块。
4. 使用 TODO。
5. 使用便签。
6. 使用倒数日。
7. 使用书签。
8. 查看今日学习时长。
9. 查看任务。
10. 查看公告。
11. 查看学习热力图。
12. 制定日历计划。
13. 上传学习资料。
14. 使用实验室知识库。
15. 与个人 AI 智能体对话。
16. 查看每日复盘。
17. 查看 AI 学习建议。

## 六、核心业务流程

### 6.1 学生使用流程

1. 管理员创建学生账号。
2. 学生通过账号密码登录平台。
3. 学生进入个人仪表盘。
4. 学生自定义仪表盘模块。
5. 学生使用 TODO、便签、倒数日、书签等工具。
6. 学生查看老师或管理员发布的任务和公告。
7. 学生制定自己的日历计划。
8. 学生上传学习资料。
9. 学生访问实验室知识库。
10. 学生通过平台访问 B 站学习链接。
11. 学生与个人 AI 伴学智能体对话。
12. 系统记录学生行为。
13. 每日 0 点系统自动复盘前一天行为。
14. 系统更新学生 memory。
15. 第二天智能体基于 memory 给出更个性化的建议。

### 6.2 老师管理流程

1. 老师登录平台。
2. 老师查看学生列表。
3. 老师查看学生学习概览。
4. 老师查看任务完成情况。
5. 老师发布任务或公告。
6. 老师为学生制定学习计划。
7. 老师查看学生每日复盘摘要。
8. 老师通过教师助手生成指导建议。
9. 老师根据数据调整后续任务。

### 6.3 管理员运维流程

1. 管理员登录后台。
2. 管理员创建学生、老师账号。
3. 管理员维护角色权限。
4. 管理员配置模型 API。
5. 管理员配置知识库、文件上传、通知渠道。
6. 管理员查看全实验室学习数据。
7. 管理员查看系统日志。
8. 管理员备份数据和维护服务。

2. 用户退出。
3. 登录状态保持。

12. 预留注册接口。
13. 注册接口默认关闭。
14. 基于角色的路由权限控制。

| 功能     | 管理员 | 老师 | 学生 |

## 7.2 学生仪表盘

### 功能说明

学生登录后默认进入个人仪表盘。仪表盘以模块化卡片形式展示学习信息，并支持拖拽、自定义布局和动效。

### 仪表盘模块

MVP 阶段支持以下模块：

1. 今日学习平台时长。
2. TODO。
3. 便签。
4. 倒数日。
5. 书签。
6. 今日任务。
7. 公告提醒。
8. 学习热力图。
9. 月日历计划。
10. AI 今日建议。
11. 最近上传文件。
12. 最近知识库访问记录。

1. 卡片可拖拽排序。

4. 卡片尺寸可调整。

7. 支持恢复默认布局。
8. 支持不同用户保存不同布局。
9. 支持基础响应式适配。

### 优先级

P0：

1. 今日学习时长。
2. TODO。
3. 便签。
4. 倒数日。
5. 书签。
6. 今日任务。
7. 公告提醒。
8. 拖拽布局保存。

P1：

1. 学习热力图。
2. 月日历计划。
3. AI 今日建议。
4. 最近文件。

P2：

1. 组件市场。

## 7.13 Memory 机制

### 功能说明

Memory 是本平台的核心能力。系统不能只是保存聊天记录，而要通过长期学习行为提取稳定、可复用的学生画像和学习习惯。

### Memory 分层

#### 1. 原始行为日志层

保存学生所有关键行为，作为复盘依据。

示例：

1. 登录时间。
2. 学习时长。
3. 任务完成情况。
4. B 站观看记录。
5. 知识库访问记录。
6. AI 对话记录。

#### 2. 每日复盘层

每天 0 点自动生成前一天总结。

内容包括：

1. 昨日学习时长。
2. 昨日主要学习内容。
3. 昨日任务完成情况。
4. 昨日拖延或异常情况。
5. 昨日知识库使用情况。
6. 昨日 AI 对话重点。
7. 明日建议。

#### 3. 短期 memory 层

保存最近一段时间的学习状态。

示例：

1. 最近正在准备某个比赛。
2. 最近在学习某门课程。
3. 最近任务完成率下降。
4. 最近经常晚上学习。
5. 最近频繁询问某个技术方向。

#### 4. 长期 memory 层

保存相对稳定的学习偏好和习惯。

示例：

1. 学生偏好清单式计划。
2. 学生更适合项目驱动学习。
3. 学生容易低估任务耗时。
4. 学生习惯通过视频入门。
5. 学生在论文阅读方面较弱。
6. 学生对 AI 智能体方向感兴趣。

### Memory 更新策略

每日 0 点执行以下流程：

1. 拉取前一天行为日志。
2. 汇总学习数据。
3. 生成每日学习复盘。
4. 提取可能有价值的信息。
5. 判断是否为短期状态。
6. 判断是否应升级为长期 memory。
7. 与已有 memory 做冲突检测。
8. 更新 memory 置信度。
9. 写入 memory 更新日志。
10. 生成第二天学习建议。

### Memory 安全要求

1. 不自动写入敏感个人信息。
2. 长期 memory 需要多次行为支撑。
3. memory 需要保留来源。
4. memory 需要保留更新时间。
5. 学生应能查看自己的部分 memory。
6. 学生应能申请删除不准确 memory。
7. 管理员可查看 memory 更新日志，但不默认查看完整私密对话。
8. 老师只能查看教学相关总结，不直接查看全部原始对话。

## 八、模型接入设计

## 8.1 模型接口选择

MVP 阶段优先使用：

> 硅基流动 OpenAI 兼容接口。

选择原因：

1. 接入方式简单。
2. 兼容 OpenAI SDK。
3. 后端改造成本低。
4. 可作为统一大模型接口。
5. 后续可平滑切换其他 OpenAI 兼容平台。
6. 适合实验室 MVP 快速开发。

## 8.2 模型调用方式

后端统一封装 LLM Provider，不在业务代码中直接写死具体模型。

调用流程：

1. 业务模块发起 AI 请求。
2. LLM Router 判断任务类型。
3. 读取 provider 配置。
4. 调用硅基流动 OpenAI 兼容接口。
5. 记录调用日志。
6. 返回结果。
7. 失败时进入降级策略。

## 8.3 任务类型

平台 AI 请求按任务类型分类：

1. student_chat：学生 AI 对话。
2. daily_review：每日复盘。
3. memory_extract：memory 提取。
4. task_breakdown：任务拆解。
5. plan_generate：计划生成。
6. knowledge_qa：知识库问答。
7. document_summary：文档总结。
8. teacher_assistant：教师助手。
9. system_summary：系统轻量总结。

## 8.4 后续模型路由预留

虽然 MVP 先用硅基流动，但系统结构需要预留多模型能力。

后续可接入：

1. ModelScope 魔搭。
2. Cloudflare Workers AI。
3. Gemini API。
4. Groq。
5. 阿里百炼。
6. 腾讯混元。
7. 智谱。
8. 本地 Ollama。
9. 本地 embedding 模型。

## 8.5 模型配置字段

模型配置表建议包含：

1. provider_name。
2. base_url。
3. api_key。

5. task_type。

7. enabled。

## 十九、风险与解决方案

## 19.1 AI 免费额度不稳定

风险：

硅基流动免费模型可能存在限流、高峰期不稳定或模型调整。

解决方案：

1. 封装统一 LLM Provider。
2. 不把业务代码写死到单一模型。
3. 保留 ModelScope、Cloudflare Workers AI、Gemini、Groq、本地模型等 fallback。
4. 记录 AI 调用日志。
5. 设置每日调用上限。
6. 对每日复盘任务做排队和失败重试。

## 19.2 B 站播放进度无法准确获取

风险：

iframe 跨域限制导致平台无法直接读取真实播放进度。

解决方案：

1. MVP 阶段记录页面停留时间。
2. 使用前端心跳判断是否仍在学习页面。
3. 支持学生手动标记完成。
4. 后续考虑自建视频资源。
5. 将视频学习记录作为参考，不作为强考核依据。

## 19.3 Memory 写入不准确

风险：

AI 可能根据少量行为误判学生偏好。

解决方案：

1. 区分短期 memory 和长期 memory。
2. 长期 memory 需要多次行为验证。
3. memory 记录置信度。
4. memory 记录来源证据。
5. 学生可查看和反馈 memory。
6. 管理员可审计 memory 更新日志。

## 19.4 通知渠道不稳定

风险：

QQ、微信个人通知方案可能不稳定或违反平台规则。

解决方案：

1. MVP 优先站内信和邮件。
2. 使用企业微信、飞书、钉钉 Webhook。
3. QQ、微信作为后续探索。
4. 不把非官方通知作为核心依赖。

## 19.5 工作站部署稳定性

风险：

实验室工作站可能断电、断网或服务异常。

解决方案：

1. Docker Compose 设置自动重启。
2. 数据库定期备份。
3. 文件定期备份。
4. Cloudflare Tunnel 设置开机自启。
5. 系统运行状态日志。
6. 后续可迁移到云服务器。

## 二十、总结

本平台的核心不是简单做一个学习管理系统，而是建设一个能够长期记录学生学习行为、自动复盘学习过程、形成个性化 memory，并通过 AI 智能体持续提供学习建议的实验室 AI 伴学平台。

MVP 阶段的关键闭环是：

> 学生使用平台 → 系统记录行为 → 每日 0 点自动复盘 → 更新个人 memory → AI 智能体提供个性化建议 → 老师和管理员查看学习状态并下达任务 → 学生继续学习并形成长期数据积累。

技术上，MVP 阶段优先使用硅基流动 OpenAI 兼容接口，降低 AI 能力接入成本，同时通过统一 LLM Provider 预留后续多模型路由能力。部署上采用实验室工作站 + Docker Compose + Cloudflare Tunnel 的方式，快速形成低成本、可访问、可维护的实验室内部平台。

当 MVP 稳定后，系统可继续扩展为多智能体协同平台，逐步实现学习规划、任务督导、知识问答、资料整理、教师助手、自动周报月报和实验室知识资产管理等能力。
